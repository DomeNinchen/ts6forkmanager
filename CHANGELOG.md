# Changelog

Every user-visible or behaviour-affecting change of this fork, newest first, grouped by the month it shipped. Entries are short on purpose: the linked pull request (or upstream issue) has the full story — root cause, design decisions and how the change was verified. Backend, frontend and sidecar are versioned independently, so each entry names the component versions that shipped it. Why this fork exists is explained in the [README](README.md#why-this-fork-exists).

## October 2026

- **The page's language tag follows the interface language.** The page was always marked as German, even when the interface showed English; it now names the language actually shown, so screen readers pronounce it correctly and browsers stop offering to translate an English page. *frontend 3.83.1* — [DomeNinchen/ts6forkmanager#301](https://github.com/DomeNinchen/ts6forkmanager/pull/301)
- **The Support System bot-flow template, reworked.** Choosing it opens a setup dialog for the values that matter — support channel, supporter groups, the messages, an optional white-/blacklist, an optional waiting room — while codec, room type and the like stay preset and tweakable in the editor. The flow creates a personal support room and moves the help-seeker in, counts how many supporters are really online (an AFK channel can be left out) and tells the user when none are, poking the supporter groups when they are; a waiting room can rename itself OPEN/CLOSED by availability; use can be limited to, or blocked for, chosen server groups. Modelled on the SinusBot script "Support Channel notifier + channel creator" by Mortis & Andreas Fink ([support-channel-mover](https://github.com/mortisdotpro/support-channel-mover), MIT). The **Count Online in Groups** flow action gains an optional "exclude channels" field. *backend 2.68.0, frontend 3.83.0* — [DomeNinchen/ts6forkmanager#300](https://github.com/DomeNinchen/ts6forkmanager/pull/300)
- **Admins choose who counts as online.** Per virtual server, the online-users number can leave out chosen server groups and the manager's own music bots, set separately for the dashboard (**Online count** button; tile and Lounge sentence) and for the embed widgets (in a widget's edit view). Server capacity still counts every occupied slot. In the Lounge layout, the customise mode now marks the four number tiles that its sentence replaces instead of offering a switch that did nothing. *backend 2.67.0, frontend 3.82.0* — [DomeNinchen/ts6forkmanager#298](https://github.com/DomeNinchen/ts6forkmanager/pull/298)
- **Music bots show real connection info in TeamSpeak.** A TeamSpeak user opening a music bot's connection info now sees its ping, packets, bytes and bandwidth instead of zeros everywhere. *backend 2.66.6* — [DomeNinchen/ts6forkmanager#297](https://github.com/DomeNinchen/ts6forkmanager/pull/297)
- **No more short crackles in music bot playback.** When the backend was briefly busy, a music bot skipped a few milliseconds of the song and then paused for one extra frame, which listeners heard as a click or short distortion without any packet loss in TeamSpeak. The bot now catches up on the late frames instead, for songs, `!play` links and radio alike. *backend 2.66.5* — [DomeNinchen/ts6forkmanager#296](https://github.com/DomeNinchen/ts6forkmanager/pull/296)
- **Five small backend fixes.** A YouTube download shared by several servers' libraries is no longer deleted while another entry still uses it; `JWT_REFRESH_EXPIRY` now actually applies (`7d`, `12h`, …); wrong uploads get 413/400 instead of 500; simultaneous widget visitors share one TeamSpeak fetch; the first-admin setup can no longer create two admins. *backend 2.66.4* — [DomeNinchen/ts6forkmanager#292](https://github.com/DomeNinchen/ts6forkmanager/pull/292)
- **Bot flows can no longer create or list privilege keys** (`tokenadd`/`tokenlist` removed from the WebQuery action's allow-list). A flow that used them now stops at that step with an error in its log. *backend 2.66.3* — [DomeNinchen/ts6forkmanager#291](https://github.com/DomeNinchen/ts6forkmanager/pull/291)
- **No more logouts when the access token expires.** A page and all tabs of a browser now share one token refresh; a backend restart no longer logs anyone out. A refresh token used a second time now ends that whole login (reuse detection). Update backend and frontend together. *backend 2.66.2, frontend 3.81.2* — [DomeNinchen/ts6forkmanager#290](https://github.com/DomeNinchen/ts6forkmanager/pull/290)
- **Lounge layout.** Settings → WebGui gets a layout choice: Cockpit (the existing look, still the default) or Lounge (two-row top navigation, calmer typography, a dashboard that opens with a sentence instead of number tiles). New base themes Petrol and Chalk. With the red accent, delete actions turn orange. The open Settings tab is now part of the address (`/settings?tab=webgui`). *backend 2.66.0, frontend 3.81.0–3.81.3* — [DomeNinchen/ts6forkmanager#286](https://github.com/DomeNinchen/ts6forkmanager/pull/286), [DomeNinchen/ts6forkmanager#288](https://github.com/DomeNinchen/ts6forkmanager/pull/288), [DomeNinchen/ts6forkmanager#293](https://github.com/DomeNinchen/ts6forkmanager/pull/293)

## Initial fork work

The changes that made this fork worth starting, before the per-change history above.

- **Video streaming stutter fixed** — three causes: a missing shared volume between backend and sidecar, a single bad RTP timestamp poisoning the A/V-sync estimate, and VP8 encoding that ran effectively single-threaded.
- **Videos are pre-downloaded and streamed from disk** instead of from a rate-limited live CDN URL, for real HD quality. Ported from [uniskela/ts6-manager](https://github.com/uniskela/ts6-manager), itself adapted from [uniplayer1/ts6-manager](https://github.com/uniplayer1/ts6-manager).
- **Multi-threaded VP8 encoding** tuned for quality per bit, and A/V sync pacing clamped against bad timestamps.
- **Streams stop when a clip ends** instead of looping, and the in-browser preview has a mute toggle.
- **Security pass after a Trivy scan** ([clusterzx/ts6-manager#80](https://github.com/clusterzx/ts6-manager/issues/80)): fixed a Go WebRTC dependency chain with 8 critical advisories, multer DoS CVEs and more. Dependabot, an on-demand Trivy workflow and branch protection enabled.
- **Bot-flow condition injection fixed**: a crafted chat message could alter what a condition checked.
- **Container restarts shut down cleanly.** Node now receives `SIGTERM`, the SSH query client waits for its connection to close, and an in-flight reconnect no longer races the shutdown — previously old sessions stayed registered on the TeamSpeak server.
- **Dependencies brought up to date:** Node 24, Express 5, Prisma 7, React 19, Vite 8, Tailwind 4, `react-router` 8, TypeScript 7, `@tanstack/react-table` 9. Unused `zod`, `react-hook-form` and `@hookform/resolvers` removed.
